# インシデント記録テンプレート

ADR#09（インシデント対応プロセス）の実装。過去のインシデント（docker crash・hook暴走 #1038・qa-workflows権限昇格等）は個別に対応・記録されてきたが型が統一されておらず、再発防止策が他リポへ横展開されにくかった。型を固定し、同じ根本原因が繰り返されているかを機械的に振り返れるようにする。

## 5項目（すべて必須）

新しい `incident_*.md` メモリを書くとき、以下の5項目を必ず埋める。

```markdown
---
name: incident_<slug>
description: "<1行要約。何が起きて何が解決済みか>"
metadata:
  node_type: memory
  type: incident
---

## 症状

<何が起きたか。エラーメッセージ・観測された挙動を具体的に>

## 初動

<検知してから何をしたか。切り分け・応急処置>

## 根本原因

<なぜ起きたか。表面的な事象ではなく真因を書く>

## 再発防止策

<恒久対策。必ず1つ以上のIssueに紐づける（下記ルール参照）>

## 横展開先

<同じ根本原因が起きうる他リポ・他コンポーネント。無ければ「なし（理由）」を明記>
```

## 運用ルール

- **再発防止策は必ず1つ以上のIssueに紐づける**。既存の「手動操作は即Issue化」ルールと連動させる
- **横展開先を「なし」にする場合も理由を書く**。書かずに省略すると、後から見た人が「横展開の検討自体をしなかった」のか「検討して対象なしと判断した」のか区別できない
- **月次でincident一覧を振り返り、同じ根本原因が2回出たらADR化する**（`repo-compass/docs/adr/` に記録）

## 既存メモリの移行

既存の `incident_*.md` は旧フォーマット（Why/How to apply形式など）で書かれているものがある。新規作成時はこのテンプレートに従うこと。既存ファイルは触れる機会があれば5項目形式に書き直すが、フォーマット統一のためだけの一括リライトは行わない（内容の劣化・文脈の欠落リスクの方が大きいため）。
